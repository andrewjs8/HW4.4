# Project and Repository Plan

## Homework 4.3 Project

### Goal

Create a reproducible Quarto PDF that communicates the results of
the diamonds, Big Ten basketball, Monte Carlo integration, and
calcium analyses, along with a reflection on my learning.

### Needs

- The Homework 4.3 Quarto source document.
- The submitted PDF.
- The diamonds dataset from ggplot2.
- games_copy.csv and calcium.csv.
- Supporting static images.
- R, RStudio, Quarto, and a LaTeX distribution.
- The tidyverse and kableExtra packages.
- Tables, plots, captions, alternative text, and cross-references.
- A GenAI Usage Appendix and an automatically generated Code Appendix.

### Steps

1. Organize the source document, data, and images within the project.
2. Clean and summarize the diamonds data by cut quality.
3. Display and interpret the three diamond dimension tables.
4. Compare home and away scoring for Penn State and other Big Ten teams.
5. Display four Monte Carlo simulations and explain the estimation process.
6. Compare the plan-informed GenAI response, generic response, and my work.
7. Include a reflection supported by specific course examples.
8. Check captions, alternative text, cross-references, and coding style.
9. Render the document to PDF and inspect the result.

## GitHub Repository

### Goal

Maintain a public repository that preserves the report, contains the
files needed to reproduce it, and demonstrates meaningful use of
branches, issues, commits, and pull requests.

### Needs

- A main branch and the dev-Andrew development branch.
- Git and Git LFS for games_copy.csv.
- A completed README and this separate plan document.
- Issues with appropriate labels.
- Descriptive commits that reference relevant issue numbers.
- Pull requests with clear titles and descriptions.
- Relative file paths and accessible supporting resources.

### Steps

1. Create the public repository and development branch.
2. Add the QMD, submitted PDF, datasets, and supporting image.
3. Track games_copy.csv using Git LFS.
4. Complete the README and plan document.
5. Correct file paths and review the QMD against the rubrics.
6. Reference relevant issue numbers in commit messages.
7. Download a fresh copy with Git LFS and check that the report renders.
8. Open a pull request from dev-Andrew into main.
9. Explain the changes and checks in the pull-request description.
10. Merge completed work and close the issues it resolves.
11. Keep main updated when making future changes.
